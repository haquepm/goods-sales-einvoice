# IRP integration plan

## Recommended first integration: IRIS IRP 6

The application is a multi-business SaaS. The integration should therefore be onboarded as a solution provider/intermediary (the relevant provider classification is selected during IRIS onboarding), rather than assuming that every tenant will share one taxpayer's direct API credentials.

Official references:
- API integration overview: https://einvoice6.gst.gov.in/content/api-integration/
- API user onboarding: https://einvoice6.gst.gov.in/content/kb/api-user-onboarding/
- API credentials: https://einvoice6.gst.gov.in/content/kb/api-credentials/
- Core API overview: https://einvoice6.gst.gov.in/content/kb/overview-of-core-apis/
- Generate IRN: https://einvoice6.gst.gov.in/content/kb/generate-irn/

## Onboarding facts to account for

- API user and taxpayer user are distinct identities. Use a dedicated organisation-controlled email for the API user.
- API users receive sandbox and production Portal IDs and API client credentials.
- Core API authentication requires the taxpayer's IRP credentials, the API user's client ID/secret and the taxpayer GSTIN.
- IRIS documents a six-hour (360-minute) authentication token validity.
- A solution provider must complete the taxpayer authorisation flow before performing core e-invoice operations for that GSTIN.
- Production access involves API testing and KYC; the IRIS onboarding page lists organisation PAN, incorporation certificate (where applicable), GST certificate, website/company information, privacy policy, terms of use, and Indian IPs for whitelisting.
- The IRP checks the standard e-invoice schema and validation rules, checks invoice duplication across IRPs, and requires the supplier status to be active on the document date.
- The IRIS production release notes state a 30-day reporting restriction from 1 April 2025 for taxpayers with AATO of ₹10 crore and above. The application should surface an invoice-age warning and not assume late registration will succeed.

## Application architecture requirements

1. Keep the provider adapter on the server only. Never expose client secrets, IRP passwords, Portal IDs or tokens to the browser.
2. Store API-user credentials as deployment secrets. Store each tenant's IRP credentials in a dedicated encrypted secret store; do not store plaintext passwords in ordinary business tables.
3. Require explicit tenant GSTIN authorisation before enabling registration.
4. Generate a payload from the immutable invoice snapshots and persisted line items, then validate it against the current official schema before sending.
5. Persist each submission attempt, provider request identifier, safe error code/message, response and timestamps. Redact credentials, auth tokens and sensitive headers from logs.
6. Handle timeouts as unknown outcomes: query the IRP by document details before retrying to avoid duplicate registration.
7. Set status to `irp_registered` only after a verified successful IRP response containing IRN, acknowledgement details, signed invoice and signed QR data.
8. Never infer or fabricate IRN, acknowledgement number/date or signed QR data.
9. Cancellation must be a separate, authorised flow within the applicable IRP time window; do not delete or silently overwrite a registered invoice.

## Required onboarding from Advanta Ads

- Register the organisation as an IRIS API user / solution provider and select the appropriate provider type for a SaaS invoicing platform.
- Complete sandbox access and integration test cases.
- Complete production KYC and IP-whitelisting requirements.
- Obtain production Portal ID, Client ID and Client Secret.
- Each customer business must complete GSTIN onboarding, set its IRP credentials and authorise the solution provider's API access.
- Provide the confirmed sandbox/production API details and credential-storage choice before enabling live submissions.

## Current state

PDF generation is implemented. Actual IRP authentication and Generate IRN calls are intentionally disabled until provider credentials, tenant authorisation and current schema validation are in place. No test or production IRN has been generated by this application.
